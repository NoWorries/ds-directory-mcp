# Lean dependency set for crawl/merge/generate CI jobs (reindex-full,
# reindex-new, reindex-shallow, submission-approve, submission-check,
# merge_shards.py) — everything ingest.py/generate_*.py actually import,
# minus:
#   - mcp[cli]: only used by server.py, which runs on Render, never in CI
#   - crawl4ai: only used by ingest.py's --spa mode (reindex-spa.yml installs
#     it separately, on top of this file)
# Every one of these jobs was installing both anyway via requirements.txt,
# which meant hundreds of shards pulling in a full browser-automation
# dependency tree (crawl4ai -> Playwright + extras) they never use — pure
# wasted Actions-minutes at real scale.
qdrant-client>=1.9.0,<2.0.0
requests>=2.31.0
beautifulsoup4>=4.12.0
lxml>=5.0.0
python-dotenv>=1.0.0
PyYAML>=6.0

# Local embeddings (see embeddings.py) — CPU-only torch explicitly, via the
# extra index below: a plain `pip install torch` on Linux pulls the CUDA-
# enabled build (multi-GB) even on a CPU-only GitHub Actions runner, which
# neither needs it nor has a GPU to use it. sentence-transformers itself
# stays off PyPI's default index (it's not a torch build) so both indexes
# are consulted. embeddings.py's lazy import means jobs that never actually
# call embed_texts()/embed_query() (submission-check's dry run, merge_
# shards.py) still pay the install cost here, but not a heavier one at
# import/run time — splitting this into its own requirements file for just
# that case wasn't worth it at one non-sharded job's expense.
--extra-index-url https://download.pytorch.org/whl/cpu
torch>=2.0.0
sentence-transformers>=3.0.0
